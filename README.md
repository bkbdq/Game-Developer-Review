# Game-Developer-Review

> 一个面向游戏行业从业者的匿名公司评价平台：说真话，不被认出来。

- 匿名问卷：https://gdr-survey.pages.dev/
- 展示站（GitHub Pages）：https://bkbdq.github.io/Game-Developer-Review/

## 这是什么

Game-Developer-Review 是一个游戏行业的匿名评价平台。你可以匿名写下自己待过的游戏公司、参与过的项目、真实的加班与福利情况、管理方式和项目体验，帮助后来者在下一次求职或合作前，看到招聘 JD 之外的另一面。

平台不做社交，不做热搜，也不追求“爆料”。我们只记录一件事：**在这家公司、这个项目里工作，真实感受是什么。**

所有提交都会经过人工审核。审核通过后，评价会以匿名形式进入公开数据，并在展示站上按公司和项目聚合展示；审核不通过的内容不会公开，也不会出现在任何搜索结果里。

## 解决什么问题

游戏行业的招聘信息高度不对称：

- 招聘 JD 写的是“扁平管理、弹性工作”，实际可能是长期 10 点后下班
- 项目是否被砍、是否频繁换方向、是否有年终，外部很难提前知道
- 在职的人不敢说，离职的人说了也容易被当成“前员工情绪”
- 零散信息散落在匿名社区、群聊和面试口头相传里，无法比较，也无法沉淀

我们想提供一个更稳定的参考系：**结构化的匿名评价 + 人工审核 + 公开可查的数据**。它不替任何人做决定，但可以让决定之前多一点事实。

## 你能看到什么

- 公司目录可按评价等级、评价数量和最近更新排序，可用公司名或别名搜索。
- 公司和项目都在满 5 篇评价后显示等级。好评率取四、五星评价在好评和差评中的比例。三星计入中评和总篇数。
- 项目发现展示精选评价、项目状态和可翻组的近期好评项目。入选项目平均分至少 4.0 / 5、累计好评率至少 70%，且近 30 天有好评，按该时段的好评篇数排序。
- 公司和项目主页可以直接进入已预填的问卷。

公司少于 5 篇评价时，公司页评价卡隐藏项目与在职时长。项目少于 5 篇时，项目页评价卡隐藏在职时长。评价日期显示到月份。

## 我们坚持什么

**匿名优先。** 不收集姓名、邮箱、手机号或账号；IP 只以加盐哈希形式短期保存，用于防刷和去重，不用于识别个人。

**人工审核。** 每条内容都会由管理员检查：脱敏、去掉广告和联系方式、处理人身攻击和未公开的商业秘密。审核不通过的内容不会进入公开数据。

**公开数据。** 审核通过的评价以 JSON 文件形式存放在公开仓库，任何人可以查看、下载和比对历史。数据格式有 schema 约束，变更可追溯。

**审核后更新。** 展示站不是实时社区，只有审核通过的内容才会触发一次静态更新。慢一点，但更干净。

## 怎么运作

```text
匿名问卷（Cloudflare Pages）
        │ 提交，写入 D1 待审队列
        ▼
管理员本地控制台（127.0.0.1）
        │ 审核、脱敏、通过或拒绝
        ▼
公开数据仓库（GitHub main）
        │ 审核通过后写入 data/
        ▼
静态展示站（Cloudflare Pages）
        │ 构建、发布
        ▼
访客浏览
```

审核通过后，本地控制台会自动从 `main` 拉取最新数据、构建并部署展示站；没有配置部署密钥的管理员也可以只完成审核。

**环境分工**：`main` 是正式环境，只包含真实数据，发布到 GitHub Pages；`dev` 额外带 `data-test/` 测试数据，发布到 Cloudflare 预览。审核通过后，两边会同步更新。

## 项目组成

| 模块 | 作用 |
| --- | --- |
| 问卷 | 匿名填写公司、项目、评分、正文和画像 |
| 提交 API | 校验、PoW、限流、去重，写入 D1 |
| 审核控制台 | 本地一键启动，任管理员用 GitHub PAT 登录 |
| 公开数据仓库 | 已审核的公司、项目和评价 JSON |
| 展示站 | Astro 静态站点，按公司和项目聚合展示 |

## 适合谁

- 正在看机会、想提前了解目标公司和项目的游戏从业者
- 想复盘团队真实口碑、但不方便公开表态的在职者
- 需要做行业研究、招聘判断或投资判断的从业者
- 愿意用匿名方式留下真实经历、帮助后来者的离职者

## 免责声明

平台上的内容均为提交者个人观点，平台只做形式审核，不构成对任何公司、项目或个人的事实认定。公司或个人如果认为内容侵犯合法权益，可以通过仓库 issue 或问卷回执号联系管理员，申请删除或更正。

项目目前处于试运行阶段，功能和数据范围会继续调整。

## 管理控制台怎么用

### 启动

1. 安装 Node.js 18+（推荐 22）
2. 双击仓库根目录的 `start-admin.cmd`
3. 浏览器会自动打开 `http://127.0.0.1:8787`；没有自动打开就手动访问

控制台只监听本机，不需要部署，也不把任何密钥写进仓库。

### 登录

控制台用 GitHub PAT 登录。按自己的身份选一种令牌：

#### 仓库主人（管理员）：fine-grained token

1. 打开 https://github.com/settings/tokens?type=beta
2. 点 **Generate new token**
3. Name 填 `gdr-admin`，Expiration 选 30–90 天
4. Resource owner 选 `bkbdq`
5. Repository access 选 **Only select repositories** → `Game-Developer-Review`
6. Permissions → Repository permissions → **Contents** 选 **Read and write**
   （`Metadata` 会自动变成 Read-only，正常）
7. 点 **Generate token**，复制 `github_pat_...`

#### 仓库协作者：classic token

GitHub 的细粒度令牌不支持写别人的个人仓库，协作者请用 classic：

1. 打开 https://github.com/settings/tokens
2. 点 **Generate new token (classic)**
3. Note 填 `gdr-admin`，Expiration 选 30 天
4. Scopes 只勾 **`repo`**
5. 点 **Generate token**，复制 `ghp_...`

两种 token 都只存在当前标签页的 `sessionStorage`，关闭标签页即失效；不要写进文件或提交到仓库。登录返回 403 时，先确认 token 对 `bkbdq/Game-Developer-Review` 有 Contents 写权限；仍不行就换另一种令牌。

> 仓库发生过转移或改名后，旧 token（尤其是 fine-grained）会失效，需要按当前 owner `bkbdq` 重新创建；管理员协作者直接改用 classic token 即可。

### 审核

1. 左侧选择一条待审提交
2. 核对公司、项目、正文、标签和在职时长；公司名会优先按提交里的 `companyId` 预选
3. 发布前完成四项检查清单并确认敏感信息提示：正文出现手机号、邮箱、身份证会被标红并禁止发布；疑似微信号 / QQ、住址会黄色提醒；与同公司已发布评价高度相似时会出现提示（可继续发布）
4. 项目可选择「匿名项目」：不公开项目名，公开数据里不关联具体项目
5. 「通过并发布」：写入公开仓 `main`，并把 D1 标记为 `approved`
6. 「拒绝」：选择内部原因（七选一，「其他」需补充说明），标记 D1 为 `rejected`，不写公开仓、不通知提交者

如果同时有多条要处理，可以先点「暂存」：暂存不会写公开仓，也不会触发展示站更新。处理完切到左侧「暂存」标签，点「全部发布」，所有暂存会合并成一次提交、一次展示站更新。暂存只保存在当前浏览器（localStorage），原始提交仍在 D1 待审队列里，不会丢。

新公司/新项目的 ID、slug 会根据名称自动生成（英文名直接转写，中文名追加稳定短哈希），也可以手动修改；名称能匹配到已有公司或项目时会优先复用。

公司 / 项目选择框支持搜索：按名称、ID、别名或旗下项目名模糊匹配并按相似度排序。控制台内置一份常见游戏公司与项目的别名库（`admin/lib/aliases.json`，可随手补充），提交里写「ZZZ」「米哈油」这类写法，打开详情时就会自动匹配到「绝区零」「米哈游」；实在没有匹配时，提交会自动落成新建公司 / 新建项目。

### 更新展示站

- 审核通过后会提交到 `main`，GitHub Pages 正式站自动构建更新
- 本机配置了 `CLOUDFLARE_API_TOKEN` 时，还会额外构建一份带 `data-test/` 的 Cloudflare 预览并部署
- 没有配置 token 时只更新 GitHub Pages；Cloudflare 预览可稍后点工具栏的「更新展示站」手动触发
- 自动部署从 `origin/main` 拉最新数据，不会使用本地未提交的修改

可选配置（文件在仓库外）：

```ini
CLOUDFLARE_API_TOKEN=...
CLOUDFLARE_ACCOUNT_ID=...
GIT_PROXY=http://127.0.0.1:7897
```

`GIT_PROXY` 只在拉取 GitHub 需要代理时填写。
