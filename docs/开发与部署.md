## 0. 环境

| 环境 | 分支 | 数据 | 展示站 | 用途 |
| --- | --- | --- | --- | --- |
| 正式 | `main` | `data/`，只含真实审核数据 | Cloudflare Pages `gdr-site` → `goodcorp.games`；GitHub Pages 镜像 → `github.goodcorp.games` | 对外 |
| 开发预览 | `dev` | `data/` + `data-test/` | Cloudflare Pages `gdr-site-dev` → `dev.goodcorp.games` | 开发预览 |
| 问卷 | `main` | 提交写入 D1 | Cloudflare Pages `gdr-survey` → `survey.goodcorp.games` | 收表 |
| 审核台 | `main` | D1 待审 + GitHub 写入 | Cloudflare Pages `gdr-admin` → `admin.goodcorp.games`；本地 `127.0.0.1:8787` | 审核发布 |

`data-test/` 里的演示数据只被 `npm run build:dev` 和 `npm run deploy:dev` 读取，`npm run build`（正式构建）会忽略它。因此 `dev` 合并到 `main` 时不会把测试数据带上线。

域名全部托管在 Cloudflare（zone `goodcorp.games`）：

| 地址 | 项目 | 说明 |
| --- | --- | --- |
| `goodcorp.games` | `gdr-site` | 展示站正式站 |
| `www.goodcorp.games` | `gdr-site` | 301 到主域 |
| `dev.goodcorp.games` | `gdr-site-dev` | 开发预览，带 `data-test/` |
| `survey.goodcorp.games` | `gdr-survey` | 问卷 + `/api/submit` |
| `admin.goodcorp.games` | `gdr-admin` | 审核台 API |
| `github.goodcorp.games` | GitHub Pages | 镜像站，DNS CNAME 到 `bkbdq.github.io`，不走 Cloudflare 代理 |

旧的 `gdr-site.pages.dev`、`gdr-survey.pages.dev`、`gdr-admin.pages.dev` 和 `www.goodcorp.games` 由各项目的 Pages Functions `_middleware.js` 按 Host 做 301 跳转（`_redirects` 不支持域名级跳转）。

## 2. 本地开发

需要 Node.js 22.23.4 或更高的受支持版本（Astro 的 engines 要求）。

```sh
npm ci
npm run dev
```

`npm run dev` 会先执行数据聚合，再启动 Astro 开发服务器。其他命令：

| 命令 | 作用 |
| --- | --- |
| `npm run data:validate` | 校验 `data/` 与 `schema/` |
| `npm run data:build` | 聚合 `data/` → `site/public/data/v1/` |
| `npm run data:build:dev` | 聚合 `data/` + `data-test/`（开发预览用） |
| `npm run build` | 正式构建：校验 + 聚合 `data/` + Astro |
| `npm run build:dev` | 开发构建：校验 + 聚合 `data/` + `data-test/` + Astro |
| `npm run preview` | 预览构建结果 |
| `npm run test:m2` | 提交链路的校验、PoW、哈希测试 |
| `npm run test:m3` | 审核、发布、拒绝与审计流程测试 |

`site/public/data/v1/` 是生成物，不入库；修改 `data/` 后重新构建即可。

展示站默认跳转到正式问卷 `https://survey.goodcorp.games/`。本地联调可用 `PUBLIC_SURVEY_URL` 指向隔离问卷，通过 `company` 和 `project` 查询参数传递名称。问卷的静态页面和展示站需要分别更新，预填才能生效。

使用 Node 22.13 或更高版本运行 `npm run dev:survey`，在 `http://127.0.0.1:4322/` 填写并提交。该服务使用项目现有的提交函数，待审记录保存在本机 `.wrangler/state/survey-preview/submissions.sqlite`。展示站联调时将 `PUBLIC_SURVEY_URL` 设置为上述地址。普通静态文件服务器只适合查看表单。

联系与作者申请表单分别读取构建变量 `PUBLIC_CONTACT_ENDPOINT` 和 `PUBLIC_REVIEW_REQUEST_ENDPOINT`。未配置时页面仅允许复制内容。接入收件服务后，联系表单发送 JSON 字段 `message`、可选 `contact`，作者表单发送 `receipt`、`type`（`correction` 或 `deletion`）和 `message`。只有 HTTP 成功且 JSON 返回 `{"ok":true}` 时，表单才会显示已收到。跨域接入需由收件服务允许展示站来源。

正式站和 GitHub Pages 镜像都使用自定义域名根路径，`SITE_BASE` 保持默认 `/`。只有把构建产物部署到子路径时才需要覆盖，例如 PowerShell：

```powershell
$env:SITE_BASE = '/some-subpath/'
npm run build
```

## 3. 数据流

```text
survey.goodcorp.games
        │ POST /api/submit
        ▼
Cloudflare D1 submissions（pending）
        │ 审核台通过后写 GitHub main 的 data/
        ▼
data/companies + data/reviews + data/taxonomy.json
        │  scripts/validate.mjs（CI 与构建前）
        ▼
scripts/aggregate.mjs
        │  生成 index.json / manifest.json / taxonomy.json / companies/*.json
        ▼
site/public/data/v1 ──► Astro 构建 ──► site/dist
        ├──► 本地审核台部署 gdr-site ──► goodcorp.games（只读 data/）
        └──► GitHub Actions 部署 Pages 镜像 ──► github.goodcorp.games（只读 data/）

dev 分支 ──► npm run deploy:dev（data/ + data-test/）──► gdr-site-dev ──► dev.goodcorp.games
```

正式构建只读 `data/`；开发构建额外读 `data-test/`，只用于 `dev.goodcorp.games` 预览。展示端只依赖 `/data/v1/*.json`，字段定义见[技术方案 §5](./技术方案.md)。首页按公司名、别名或项目名搜索，项目卡片链接至该项目的全部公开评价；推荐按数据生成日（北京时间）往前含当天 30 个自然日的好评数排序，4、5 星计为好评。

## 4. 数据维护

- 公司元数据与项目列表：`data/companies/{companyId}.json`
- 首页轮播每个项目展示一条评价正文。要指定哪一条，在公司文件对应的 `projects[]` 项中填 `featuredReviewId`，值为该项目已公开评价的 `id`。没有匹配时取该项目最近一条四、五星评价；没有好评时取最近一条公开评价。
- 单条已审核评价：`data/reviews/{companyId}/{reviewId}.json`
- 枚举字典：`data/taxonomy.json`

`data/companies` 与 `data/reviews` 初始为空，真实数据由控制台审核通过后写入；`data-test/` 只放开发预览用的演示数据，正式构建不会读取。展示站在没有数据时显示空状态。

新增或修改数据后至少运行 `npm run data:validate`。公开数据不得出现姓名、联系方式、IP、UA、审核人等字段，校验脚本会拦截。

## 5. 提交链路（M2）

已实现：

- `survey/`：原生表单 + JS 增强，15 秒总预算、5 秒单次超时、3 秒慢网提示、取消等待、本地草稿保留 7 天、复制 / 邮件兜底
- 公司名支持从展示站目录选择已有公司（3 秒超时、7 天缓存、失败退回自由输入），提交时附带 `companyId` 提示
- `POST /api/submit`：urlencoded 与 JSON 双通道、16 KB 限制、字段校验、蜜罐、PoW、IP 哈希限流、24 小时内容去重、幂等写入
- D1 `submissions` 表：`pending` / `approved` / `rejected`，审核字段与 `audit_log` 审计表

本地逻辑验证：

```sh
npm run test:m2
```

部署步骤：

1. 复用已有 D1 `goodcompany`，执行迁移：

```sh
npx wrangler d1 execute goodcompany --remote --file survey/migrations/0001_submissions.sql
npx wrangler d1 execute goodcompany --remote --file survey/migrations/0002_requests.sql
```

2. 创建 Cloudflare Pages 项目 `gdr-survey`，构建根目录为仓库根，静态目录为 `survey`，Functions 自动使用根目录 `functions/`；绑定 D1 变量 `DB`。
3. 展示站项目 `gdr-site` 也需要绑定同一个 D1 `DB`，并配置 `IP_SALT`，用于 `/api/requests`、`/api/contact` 和回执状态查询。
4. 配置 Pages 环境变量：`IP_SALT`（密钥）、`POW_SECRET`（密钥，用于签发 PoW 挑战）、`ALLOWED_ORIGINS=https://survey.goodcorp.games,https://gdr-survey.pages.dev,https://goodcorp.games,https://dev.goodcorp.games,https://github.goodcorp.games`、`POW_DIFFICULTY=3`。GitHub Pages 镜像的申请/联系表单通过 `site-deploy.yml` 里的 `PUBLIC_REVIEW_REQUEST_ENDPOINT` / `PUBLIC_CONTACT_ENDPOINT` 指向 Cloudflare 站点 API。
5. 给项目绑定自定义域名 `survey.goodcorp.games`，DNS 使用 Cloudflare 代理的 CNAME 指向 `gdr-survey.pages.dev`。
6. 部署问卷：

```sh
npm run deploy:survey
```

7. 如需邮件兜底，把 [survey/index.html](../survey/index.html) 的 `data-fallback-email` 填成真实邮箱；留空时隐藏「邮件提交」按钮，「复制内容」仍可用。

## 6. 审核控制台（M3）

### 6.1 服务端 API

`admin/functions/` 提供 `/api/admin/*` 接口，部署在独立 Pages 项目 `gdr-admin`：

- `GET /api/admin/me`：校验 GitHub PAT
- `GET /api/admin/submissions?status=pending`：读取 D1 待审列表
- `POST /api/admin/submissions/{id}`：`approve` / `reject`
- `GET /api/admin/requests?status=received`：删除/更正申请列表
- `POST /api/admin/requests/{id}`：处理或驳回申请
- `GET /api/admin/contacts?status=received`：联系消息列表
- `POST /api/admin/contacts/{id}`：标记联系消息已处理

审核台右上角「申请 / 联系」进入 `requests.html`，可以在页面内删除公开评价、更正正文、驳回申请或标记联系消息。

需要给 `gdr-admin` 绑定 D1 变量 `DB`，并设置 `GITHUB_OWNER=bkbdq`、`GITHUB_REPO=Game-Developer-Review`（可选 `ADMIN_LOGINS`）。项目绑定自定义域名 `admin.goodcorp.games`，DNS 使用 Cloudflare 代理的 CNAME 指向 `gdr-admin.pages.dev`。

部署：

```sh
npm run deploy:admin
```

API 不保存任何密钥；每次请求用调用者的 GitHub PAT 校验身份和仓库写权限。凭据优先用 fine-grained PAT（Contents 读写）；如果返回 403，再换 classic PAT（`repo` scope）。

### 6.2 本地一键控制台

`start-admin.cmd` 启动 `tools/admin-launcher.mjs`：

- 静态服务 `admin/`，监听 `127.0.0.1:8787`
- 本地页面调用同源 `/api/admin/*`，由本地 Node 服务转发到 `https://admin.goodcorp.games`（可用环境变量 `ADMIN_API_ORIGIN` 改上游）
- 转发请求自动使用系统代理（`HTTPS_PROXY` 或 Windows 系统代理设置），无需手动配置；没有代理时直连
- 「暂存」把整理好的草稿存在浏览器 `localStorage`，不写公开仓；「暂存」标签里的「全部发布」把多条评价合并为一次 commit、一次展示站部署
- 提供 `POST /api/local/deploy` 和 `GET /api/local/status`
- 不保存服务端密钥；管理员各自粘贴自己的 GitHub PAT

> 本地控制台不是离线工具：待审数据在 Cloudflare D1 上，必须能访问审核 API。中国大陆网络直连 `pages.dev` 通常不通，现在统一走自定义域名 `admin.goodcorp.games`，仍可能需要代理。

审核通过后，本地控制台会调用 `/api/local/deploy` 自动部署 Cloudflare 正式站：

1. `git fetch origin main`
2. 在仓库外 `../.gdr-deploy` 准备干净的 main worktree
3. `npm run build`（只读 `data/`）；`package-lock.json` 未变化时跳过 `npm ci`
4. `npx wrangler pages deploy dist --project-name gdr-site --branch main`

批量发布时整批只走一次上述流程；同一笔审核提交到 `main` 后，GitHub Actions 的 `site-deploy` 会自动构建并更新 GitHub Pages 镜像（同样只读 `data/`）。因此一次审核会同步更新两个入口：`goodcorp.games` 和 `github.goodcorp.games`，两边都只含真实数据。

开发预览不再随审核发布。需要看 `data-test/` 演示数据时，在 `dev` 分支执行：

```sh
npm run deploy:dev
```

该命令用 `data/` + `data-test/` 构建并部署 `gdr-site-dev`，对应 `dev.goodcorp.games`。

配置从 `.secrets/cloudflare.env` 读取（仓库外）：

```ini
CLOUDFLARE_API_TOKEN=...
CLOUDFLARE_ACCOUNT_ID=...
GIT_PROXY=http://127.0.0.1:7897
```

没有配置 `CLOUDFLARE_API_TOKEN` 时只完成审核，不部署；控制台工具栏的「更新展示站」可手动触发。

## 7. 发布与 CI

- `data-validate.yml`：数据变更时校验 schema、引用完整性和敏感字段
- `site-deploy.yml`：push 到 main 时构建 GitHub Pages 镜像（只读 `data/`），自定义域名 `github.goodcorp.games`；构建使用根路径 `SITE_BASE=/`
- Cloudflare 正式站 `gdr-site`：由本地审核台审核通过后用 `npm run build` 构建并上传，读取 `data/`，对外 `goodcorp.games`
- 开发预览 `gdr-site-dev`：在 `dev` 分支执行 `npm run deploy:dev`，读取 `data/` + `data-test/`，对外 `dev.goodcorp.games`
- 问卷 `gdr-survey`：`npm run deploy:survey`
- 审核台 `gdr-admin`：`npm run deploy:admin`
- D1 清理 Worker `gdr-cleanup`：把真实 `database_id` 填入 `worker/wrangler.toml` 后执行 `npm run deploy:cleanup`；每天清理 approved 7 天、rejected 30 天、pending 90 天、ipHash 30 天、申请/联系记录 90 天
- D1 备份：`npm run d1:export` 导出到本地 `.backups/`（已忽略，不提交）
- 所有 Cloudflare 部署命令都需要本机环境变量 `CLOUDFLARE_API_TOKEN` 和 `CLOUDFLARE_ACCOUNT_ID`
