# goodcorp · 需求文档总览

> 读者：接手开发的朋友 ｜ 版本：v3.1（2026-11-24，补充实现状态核对）
> 本套文档只从**产品与用户视角**描述：用户看到什么、能做什么、数据是什么、规则是什么；不涉及技术实现
> 本文是索引，具体设计见各模块文档

---

## 1. 产品一句话

游戏行业的匿名公司评价平台：给待过的公司和项目打分、写下经历，展示端用 Steam 式等级（好评如潮 / 褒贬不一）聚合呈现。品牌 `goodcorp`，基调是“让行业更好”，不爆料、不煽动。

---

## 2. 第一阶段目标

> 一个陌生人从展示站进入问卷 **不超过 2 次点击**，除写正文外，填写操作在 **1 分钟内**完成；审核通过后，公司页出现一个**不会被单条评价定性**的等级。

两个前提：

1. **入口足够短**：任何页面都能一眼看到“写评价”，点进来公司/项目已经填好
2. **表单足够轻**：只问最必要的几项，其余全部选填

## 5. 已拍板的产品决策

| # | 决策 |
| --- | --- |
| 1 | 公司用**真名**，项目名照实展示（可选择不公开） |
| 2 | 评级门槛低于 Steam：5 篇起评、20 篇“特别”、50 篇“如潮” |
| 3 | 样本过少只显示“评分过少”，不显示等级、不显示好评率 |
| 4 | 不区分在职/离职；画像只有**在职时长**一项 |
| 5 | 没有岗位、城市字段；只有综合评分，没有分项评分 |
| 6 | 公司别名只用于内部匹配与搜索，**不在页面展示** |
| 7 | 项目可以不公开：用户勾选后，该评价在公司页归入“匿名项目” |
| 8 | 单管理员，只承诺“定期审核”，不承诺具体时效；拒绝不通知用户 |
| 9 | 公司目录由产品方提供清单，开发只负责录入 |
| 10 | 全站只保留“联系我们”（站内表单），不做其他反馈入口 |
| 11 | 不做在职时长的分布统计，只在单条评价上显示 |
| 12 | 评价不设硬性字数要求，页面不显示字数上限 |

## 6. 用户要填的字段（全部）

| 字段 | 必填 | 形式 | 说明 |
| --- | --- | --- | --- |
| 公司 | 是 | 文本（可联想已有公司） | 找不到就照实填，审核时归并 |
| 项目 | 否 | 文本（可联想） | 只评价公司可不填 |
| 不公开项目名 | 否 | 勾选 | 勾选后，该评价归入“匿名项目” |
| 综合评分 | 是 | 1–5 星 | 唯一的分值 |
| 在职时长 | 否 | 四个区间选一个 | 小样本时不在页面显示 |
| 评价正文 | 是 | 长文本 | 只写事实与感受 |
| 同意声明 | 是 | 勾选 | 自己确认真实、不含个人信息 |

> 就这 7 项，没有岗位、没有在职状态、没有城市、没有分项打分。

## 7. 跨模块验收

- [x] 任意页面 ≤2 次点击进入问卷，公司/项目已预填
- [x] 除写正文外，填表操作 1 分钟内完成
- [x] 公司页显示等级 + 好评率 + 好评/中评/差评条数
- [x] 5 篇以下显示“评分过少”，不显示等级与好评率
- [x] 单条评价不会产生任何等级
- [x] 3 星按中评计算，不计入好评率分母
- [x] 评价卡只显示“在职时长”，不再有岗位/在职状态/城市
- [x] 公司页评价可按“匿名项目”单独筛选
- [x] 勾选“不公开项目名”的评价，在公司页显示为“匿名项目”，不出现在任何项目页
- [x] 小样本（<5 篇）时不显示在职时长与项目信息
- [x] 审核台未过红线、含个人信息时无法发布
- [x] 个人可凭回执申请删除/更正；公司走“联系我们”
- [x] “联系我们”表单可在审核台看到
- [x] 全站没有字数上限提示，也没有“吐槽/牛马/996/爆料”字样
- [x] 隐私页写的保留期与实际处理一致
