# M2 · 评级

> 模块：把一堆评分变成一个可信的结论 ｜ 读者：产品 + 开发
> 关联：M5 数据（评价内容）、M1 展示（等级怎么显示）
> 状态：已有一版，只用在项目上，本期重做并扩展到公司

---

## 1. 模块职责

- 定义“好评率”和“等级”怎么算，全站只此一套
- 决定样本多少才配显示等级
- 让用户一眼看懂：这家公司/这个项目，整体风评如何

---

## 2. 现状（用户看到的样子）

| 位置 | 现在看到什么 | 问题 |
| --- | --- | --- |
| 项目卡、项目页 | 有等级，如“好评”“褒贬不一” | 只有项目有，公司没有 |
| 公司页 | 只有“综合评分 4.2 / 5” | 核心对象没有结论 |
| 只有 1 条评价时 | 项目页直接显示“差评” | 一条情绪评价就能定性一家公司 |
| 全是 3 星时 | 好评率 0%，显示“差评” | 3 星在卡片上写“中评”，算法却当差评 |
| 样本要求 | 好评如潮要 500 篇、特别好评要 50 篇 | 新站一年内都到不了，等级形同虚设 |

### 3.3 用户能读懂的规则

- **好评** = 4–5 星；**中评** = 3 星；**差评** = 1–2 星
- **好评率** = 好评 ÷（好评 + 差评），中评不参与计算
- **5 篇以下**：不评级，只显示已收到的评价
- **5 篇起**：按下面的门槛给等级

| 好评率 | 样本 | 等级 |
| --- | --- | --- |
| ≥95% | ≥50 篇 | 好评如潮 |
| ≥80% | ≥20 篇 | 特别好评 |
| ≥80% | 5–19 篇 | 好评 |
| 70–79% | ≥5 篇 | 多半好评 |
| 40–69% | ≥5 篇 | 褒贬不一 |
| 20–39% | ≥5 篇 | 多半差评 |
| <20% | ≥20 篇 | 特别差评 |
| <20% | 5–19 篇 | 差评 |
| — | 少于 5 篇 | 评分过少 |

> 中评单列，不参与好评率，所以“全是 3 星”不会变成差评，而是“褒贬不一”。

## 4. 后台数据（评级需要的口径）

### 4.1 需要的数据

评级只用两样东西，别的都不参与：

| 数据 | 用途 |
| --- | --- |
| 每条评价的综合评分（1–5） | 分子分母 |
| 每条评价的发布日期 | 判断“近 30 天好评数”（只用于排序） |

- 不使用：岗位、城市、在职时长、审核人、提交时间
- 不区分在职/离职（本来也没有这个字段）

### 4.2 统计规则

- 公司等级 = 该公司**全部已发布评价**的统计（包含“匿名项目”的评价）
- 项目等级 = 该项目**全部已发布评价**的统计（不含匿名项目）
- 同一套规则，不做加权、不做“老评价打折”
- 评价被删除后，下一次更新即重新计算
- 历史评价（没有新字段）照常参与，不需要回填

### 4.3 展示边界

- 评价数 <5：公司页/项目页不显示等级与好评率，只显示“评分过少”和已有评价
- 数据更新是“审核通过后统一更新”，不是实时
