# M3 · 问卷

> 模块：匿名填写与提交 ｜ 读者：产品 + 前端
> 关联：M5 数据、M6 删除入口
> 状态：已上线，本期精简字段

---

## 1. 模块职责

- 让用户在一分钟内完成除正文以外的填写
- 从公司页/项目页点进来时，不用重复输入
- 提交后清楚告诉用户：已收到、审核通过才展示、回执要自己保存

---

## 2. 现状（用户看到的样子）

| 项目 | 现状 |
| --- | --- |
| 字段 | 公司名、项目名、综合评分、正文、“希望被吐槽的内容”、岗位、司龄、在职状态、城市、同意声明 |
| 字数 | 正文和另一个输入框都标了字数上限 |
| 预填 | 没有，从公司页进来也要手输公司名 |
| 草稿 | 自动保存在本机，7 天内可恢复 |
| 成功页 | 显示回执编号，并说“便于后续查询或删除” |
| 文案 | 有“希望被吐槽的内容”这类表达 |

问题：

| 编号 | 问题 | 用户感受 |
| --- | --- | --- |
| 1 | 字段太多 | 像填表，不像写评价 |
| 2 | 岗位/在职状态/城市 | 与“匿名”承诺矛盾，小公司更容易被认出 |
| 3 | 字数提示 | 吓人，还没写就先看到上限 |
| 4 | 无预填 | 从公司页点进来还要再找一次公司 |
| 5 | 成功页承诺查询/删除 | 实际没有入口，属于过度承诺 |
| 6 | 文案基调 | “吐槽”与建设性定位不符 |
| 7 | 项目只有“填/不填” | 想提项目但不想公开的人没有选择 |

## 3. 前端展示设计

### 3.1 目标

- 进入问卷 ≤2 次点击
- 除写正文外，其余操作 **1 分钟内**完成
- 字段越少越好，能选填就选填

### 3.2 优化点

| 编号 | 优化 | 描述 | 优先级 |
| --- | --- | --- | --- |
| FE-1 | 精简字段 | 只保留：公司、项目、不公开项目名、综合评分、在职时长、正文、同意声明 | P0 |
| FE-2 | 去掉岗位 | 问卷不再问岗位，展示端也不再出现岗位 | P0 |
| FE-3 | 去掉在职状态 | 不再区分在职/离职，只问“在职时长” | P0 |
| FE-4 | 去掉城市 | 不再收集城市，减少识别风险 | P0 |
| FE-5 | 去掉“想对后来者说的话” | 这个字段整体移除 | P0 |
| FE-6 | 去掉字数提示 | 页面不显示字数上限；内容过长由审核处理 | P0 |
| FE-7 | 不公开项目名 | 项目栏下方勾选“不公开项目名”；勾选后该评价在公司页归入“匿名项目”，不进任何项目页 | P0 |
| FE-8 | URL 预填 | 从公司页/项目页进入时，公司、项目已填好，顶部显示“正在评价：XX · YY” | P0 |
| FE-9 | 在职时长 | 选填，四个区间（1 年以内 / 1–3 年 / 3–5 年 / 5 年以上），说明“类似 Steam 的游戏时长” | P0 |
| FE-10 | 成功页 | 回执 + “经审核通过后，会在网站显示” + 查看公司页 + 再写一条 + 申请删除/更正 | P0 |
| FE-11 | 回执提示 | 显著提醒：回执只出现一次，网站不会展示、不会再次提供，请自行保存 | P0 |
| FE-12 | 文案修正 | 介绍语改为记录事实与感受，去掉“吐槽”类表达 | P0 |
| FE-13 | 单列移动端 | 手机上单列、按钮好点、错误提示指到具体字段 | P1 |

### 3.3 字段与顺序

| 顺序 | 字段 | 必填 | 形式 |
| --- | --- | --- | --- |
| 1 | 公司 | 是 | 文本，可联想已有公司 |
| 2 | 项目 | 否 | 文本，可联想 |
| 3 | 不公开项目名 | 否 | 勾选（填了项目才出现） |
| 4 | 综合评分 | 是 | 1–5 星 |
| 5 | 在职时长 | 否 | 四个区间选一个 |
| 6 | 评价正文 | 是 | 长文本 |
| 7 | 同意声明 | 是 | 勾选 |

### 3.4 页面结构

```
[顶部] 匿名评价 · 审核后展示
[提示] 正在评价：百科不大全有限公司 · 超绝wiki游戏百科
[表单]
  公司（已填，可改）      项目（已填，可改）
  ☐ 不公开项目名
  综合评分（1–5 星）
  在职时长（选填，四选一）
  评价正文
  ☐ 我确认是本人真实经历，不含姓名、联系方式等个人信息
[提交]
[成功]
  回执编号：xxxx
  ⚠ 请立即保存。回执只在这里出现一次，网站不会展示，也不会再次提供。
  经审核通过后，会在网站显示。
  [查看该公司页面] [再写一条] [申请删除/更正]
```

## 4. 后台数据（提交之后发生什么）

| 阶段 | 用户可见 | 平台内部 |
| --- | --- | --- |
| 提交成功 | 回执 + “经审核通过后显示” | 进入待审队列，状态“待审” |
| 审核中 | 无（不提供审核状态查询） | 管理员可见原文；平台不公开 |
| 审核通过 | 展示站出现该评价 | 状态改为“已通过”，原始提交 7 天后清理 |
| 审核拒绝 | 无通知，页面不出现 | 状态改为“已拒绝”，30 天后清理 |
| 申请删除 | 在删除页凭回执查看处理结果 | 从公开数据移除，保留审核记录 |

- 提交内容不直接公开，必须经过人工审核
- 拒绝不通知用户，也不提供“未通过”状态查询
- 用户不需要注册、不需要留联系方式
- 同一设备/网络短时间内重复提交会被限制（用户看到“提交太频繁”）
