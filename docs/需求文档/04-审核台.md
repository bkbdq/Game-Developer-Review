# M4 · 审核台

> 模块：人工审核与发布 ｜ 读者：产品 + 开发
> 关联：M3 问卷、M5 数据、M6 删除
> 状态：已上线，本期补安全校验

---

## 1. 模块职责

- 待审内容只有一个人工入口：核对、修改、通过或拒绝
- 通过即公开，拒绝永不公开；两种情况都留内部记录
- 让一个人也能高效处理：清单化、模板化、提示化

---

## 2. 现状（管理员看到的样子）

| 能力 | 现状 |
| --- | --- |
| 登录 | 用 GitHub 账号授权，token 存 cookie，30 天内免登录 |
| 列表 | 待审 / 暂存 两个分类，可搜索 |
| 详情 | 公司、项目、评分、正文、画像（岗位/司龄/在职/城市）、标签 |
| 暂存 | 先存本地，稍后一次性发布 |
| 通过 | 写入公开数据，标记已通过，并触发展示站更新 |
| 拒绝 | 手写原因，标记已拒绝 |

问题：

| 编号 | 问题 | 影响 |
| --- | --- | --- |
| 1 | 没有发布前检查清单 | 靠记忆，容易漏 |
| 2 | 没有敏感信息检查 | 手机号、邮箱可能被放行，公开后才发现 |
| 3 | 拒绝原因靠手写 | 口径不一，事后难统计 |
| 4 | 没有相似内容提示 | 重复提交、刷评靠人眼 |
| 5 | 项目只有“匹配到”或“新建” | 用户要求匿名的项目无法归类 |
| 6 | 没有删除/联系消息入口 | 用户申请只能线下沟通 |
| 7 | 待审没有等待时长 | 看不出积压 |

## 3. 前端展示设计（审核台界面）

### 3.1 优化点

| 编号 | 优化 | 描述 | 优先级 |
| --- | --- | --- | --- |
| FE-1 | 发布前检查清单 | 四项必勾：无姓名/联系方式/身份证/住址；无未公开代号或商业秘密；无人身攻击；公司与项目归属正确。未勾完不能通过或暂存 | P0 |
| FE-2 | 敏感信息检查 | 正文里出现手机号、邮箱、身份证时标红并禁止发布；出现微信/QQ、具体住址时给黄色提醒 | P0 |
| FE-3 | 相似内容提示 | 与同公司已发布评价对比，相似度高时提示“可能与已有评价重复”，并列出相似的几条 | P0 |
| FE-4 | 拒绝原因（内部） | 下拉选择：含个人信息 / 疑似不实 / 广告引流 / 与公司无关 / 重复提交 / 涉及商业秘密 / 其他。原因只进内部记录，**不通知提交者** | P0 |
| FE-5 | 匿名项目归类 | 项目选择里增加“匿名项目”：用户勾选了“不公开项目名”，或审核员判断不宜公开时选它 | P0 |
| FE-6 | 在职时长核对 | 详情区展示并在必要时修正（四区间） | P0 |
| FE-7 | 待审等待时长 | 列表显示“已等待 3 天”，超过 7 天标黄（只提示积压，不承诺时效） | P1 |
| FE-8 | 删除/更正队列 | 新增分类：回执、类型、原因、关联评价；可执行删除或驳回 | P1 |
| FE-9 | 联系消息 | 新增分类：用户通过“联系我们”提交的内容；可标记已处理 | P1 |
| FE-10 | 状态与错误提示 | 登录失效、网络失败、发布失败分别给明确提示和下一步动作 | P1 |

### 3.2 缺失功能（本期不做）

| --- | --- | --- | --- |
| F-1 | 批量通过 | 仅限已匹配公司、无敏感提示的条目 | P1 |

### 3.3 详情区结构（改后）

```
[摘要] 提交编号 / 公司原文 / 项目原文 / 评分 / 提交时间 / 风险标记
[匹配] 公司（可新建）/ 项目（可新建，或选“匿名项目”）
[评分] 综合评分
[在职时长] 四区间
[正文] 正文（敏感片段标红）
[检查清单] 四项必勾
[相似提示] 命中时出现
[操作] 通过并发布 / 暂存 / 拒绝
```

### 3.4 审核红线（写进页面，与关于页一致）

1. 不含真实姓名、联系方式、身份证号、住址
2. 不含未公开的项目代号、内部系统名或商业秘密
3. 不含人身攻击、侮辱性表述
4. 公司与项目归属正确，正文与所选对象一致

## 4. 后台数据（审核流转）

### 4.1 状态

| 状态 | 含义 | 用户能看到的 |
| --- | --- | --- |
| 待审 | 已收到，等待处理 | 无（不提供状态查询） |
| 已通过 | 已公开 | 网站上的评价 |
| 已拒绝 | 不公开 | 无，不通知 |

- 审核台只处理“待审”
- 拒绝必须填原因；原因只进内部记录，不公开、不通知
- 通过后公开评价才出现，原始提交 7 天后清理

### 4.2 记录

每次操作都记录：谁、什么时候、对哪条、通过还是拒绝、原因。记录不含评价正文，长期保留。

### 4.3 发布

- 一条通过 = 公开数据里多一条评价，展示站下次更新后可见
- 暂存的多条可以一次发布，避免频繁更新
- 删除/更正同样走审核台，并记录

### 4.4 权限

- 单管理员，用 GitHub 账号授权登录
- 审核台只在本机打开，不对公网暴露
- 令牌存浏览器 cookie，30 天内免登录，退出登录即清除
