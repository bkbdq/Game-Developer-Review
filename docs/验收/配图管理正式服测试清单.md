## 一、推送后的线上检查

下列复选框供后续发布复用，本次执行结果见上表。

- [ ] **部署**　在 GitHub Actions 中找到此次提交，确认 `admin-deploy`、`site-deploy` 的 Cloudflare 部署均成功。打开正式展示站首页、公司目录与项目详情，确认仍可访问。[部署记录](https://github.com/bkbdq/Game-Developer-Review/actions)
- [ ] **R2 绑定**　打开下方探测地址。应返回 HTTP 404 和 JSON 消息「图片不存在」，表明正式接口已读取存储桶。若返回 503「审核后台尚未绑定配图 R2 存储桶」，在 Cloudflare Pages 项目 `gdr-admin` 的 Production 环境将目标桶绑定为 `ARTWORK`，重新部署审核项目后复测。若收到 200 和 HTML，检查审核 Functions 部署及路由。[探测地址](https://admin.goodcorp.games/api/artwork/c_readcheck/studio/0123456789abcdef/card.webp) · [Cloudflare 绑定说明](https://developers.cloudflare.com/pages/functions/bindings/#r2-buckets)
- [ ] **上传权限**　匿名 POST 到 `https://admin.goodcorp.games/api/admin/artwork/c_readcheck/studio/0123456789abcdef`，应返回 HTTP 401 和 JSON 消息「缺少登录凭证」。这一步无需提供图片。

## 二、用正式数据从选图走到展示

- [ ] **进入工具**　在最新正式版检出目录运行 `start-artwork.cmd`。搜索和裁切由本机工具执行，提交指向正式审核后台。核对目录内真实条目名称、类型和已配图状态。
- [ ] **共享 DeepSeek**　在未设置 `DEEPSEEK_API_KEY` 的电脑上启动最新版，使用原有审核台身份找图。确认候选图可预览，注明本次实际来源，区分 DeepSeek 命中与常规补图。
- [ ] **查找与预览**　用游戏名搜索 Steam 或 TapTap 候选图，再用「柚子猫」试一次 DeepSeek 公司找图。检查候选是否为该公司 Logo、是否附有能核对的出处、能否点选并预览。记录本次实际命中的来源。找图未命中时记下提示，可用已有授权图片继续验证存储。
- [ ] **公司与项目各提交一次**　核对图片后点「提交配图」。收到「图片已保存至 R2，配图记录已更新」后记录提交号。到 GitHub 对照该次变更，应只更新对应条目的 `site/public/images/catalog/<公司ID>/<studio 或项目ID>/current.json`，其中包含 `storage: "r2"`、版本、来源和裁切参数。提交失败时核对原版本仍然生效。
- [ ] **直接读图**　无登录访问 `https://admin.goodcorp.games/api/artwork/<公司ID>/<studio 或项目ID>/<版本>/<文件名>.webp`。以下展示图均应返回 HTTP 200、`Content-Type: image/webp`，且图片可解码。原图不入存储桶：访问 `.../source.webp` 应返回 HTTP 404。

| 条目 | 展示图及像素尺寸 |
| --- | --- |
| 公司 | banner 1440 × 400，card 720 × 240 |
| 项目 | cover 1280 × 720，card 640 × 320，detail 1080 × 480 |

- [ ] **访客展示**　等上一步配图提交触发的 `site-deploy` 成功后，用无痕窗口打开公司目录、公司主页、项目发现和项目详情。核对卡片与大图的归属、裁切及清晰度，确认浏览器加载了记录中的 R2 版本。首页轮播仅在该项目入选时核对。
- [ ] **重新编辑**　关闭并重新打开配图工具，找到同一条目，点「编辑配图」。应按 `current.json` 记录的出处重新读取原图，恢复来源和裁切位置；出处页面已失效时给出明确提示，可改用搜索或本机选图。把裁切调整到最终需要的位置并保存，核对新版本上线。
- [ ] **旧图兼容与审核回归**　如存在旧版 Git 配图，检查其缩略图和原图可读。进入审核台已有的数据维护页、待审队列和审计日志，确认正常加载。

## 恢复配图

如已发布的图片有误，回到配图管理换回正确图片并提交。需要精确恢复旧版本时，使用新的 Git 提交恢复该条目先前的 `current.json`。若此次是首张配图，可在新提交中移除该条目的新增记录。等展示站部署完成后，用无痕窗口确认该条目恢复。记录恢复提交号。
